在 RAG 里，召回阶段有哪些值得优先做的优化？我们现在的知识库大概 2 万条 chunk。
14:32

知问 知识库增强 检索 86ms · 用时 4.2s

在 2 万条 chunk 的规模下，建议优先做低成本、收益确定的三件事，而不是一上来就换更大的向量模型。

1混合检索（Hybrid Search）

把 BM25 的精确词命中与向量检索的语义召回融合，尤其适合你的资料里存在大量产品名、接口名和版本号的情况。根据资料中的实验，混合检索可将 Recall@5 提升约 12%–18%1。

  • 先用 RRF（倒数排名融合）做粗融合，稳定且无需调权重；
  • 有标注数据后，再切换为加权分数融合，并做归一化。

2查询改写（Query Rewriting）

用户的原始问题往往口语化、缺少上下文。用一次低成本的小模型调用，将问题改写为「检索友好」的查询，并补全多轮对话中的指代2。

3重排（Rerank）

召回 Top 20 后用 Cross-Encoder 重排到 Top 5。它通常比更换 Embedding 模型更划算，但会增加约 80–150ms 延迟；建议先离线评估再上线。

混合检索里 BM25 和向量分数怎么融合比较稳妥？

知问 知识库增强 检索 72ms · 用时 3.6s

稳妥的顺序是：先 RRF，再考虑加权融合。两种分数的量纲不同，直接相加会让某一路主导，必须先处理。

  • RRF：只使用排名，按 1 / (k + rank) 累加，k 取 60 左右。无需归一化，冷启动最稳；
  • 加权分数融合：先做 min-max 或 z-score 归一化，再按业务调 0.3 × BM25 + 0.7 × 向量；
  • 用 100–300 条带标注的 query 做离线评测，以 Recall@5 和 nDCG@10 选择方案。

如果团队还没有标注集，建议先用 RRF 上线，同时把线上「无引用 / 点踩」的 query 收集起来，两周后就能做第一轮融合策略评估1。
